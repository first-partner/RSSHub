# 2-5 / 2-6 / 2-7 承認フロー・炎上対応・アカウント管理

## 1. 承認フロー

```
[起案] 運用担当が DB-A に起票（ステータス: 作成中）
   ↓ 本文・画像・リンクを揃える
[セルフチェック] 03_NG禁止事項 の投稿前チェックリストを実施
   ↓ ステータス: レビュー待ち
[レビュー] レビュー担当が文面・事実・権利を確認
   ↓ 差戻しは「修正中」に戻す（コメントで理由必須）
[承認] 承認者が承認（承認日を記録）→ ステータス: 承認済
   ↓
[予約/投稿] ステータス: 予約済 → 投稿済（投稿URLを記録）
```

| 役割 | 担当者 | 権限 |
|---|---|---|
| 起案 | 【要記入】 | 下書き作成 |
| レビュー | 【要記入】 | 差戻し |
| 承認 | 【要記入】 | 公開の可否を決定 |
| 法務確認 | 【要記入】 | C区分（法令関連）の最終判断 |
| 最終責任者 | 【要記入】 | 炎上時の対外判断 |

### 承認の要否

| 投稿種別 | 承認 |
|---|---|
| 通常のノウハウ・共感系 | レビューのみ（承認省略可）※運用開始3ヶ月は全件承認 |
| 告知・キャンペーン・価格に触れるもの | 承認必須 + 法務確認 |
| 時事・社会的話題 | 承認必須 |
| お詫び・障害報告 | 最終責任者の承認必須 |
| リプライ（テンプレ範囲内） | 承認不要 |
| リプライ（テンプレ外） | レビュー必須 |

## 2. リスク・炎上対応フロー

### レベル定義

| レベル | 状況 | 初動時間 | 対応 |
|---|---|---|---|
| L0 監視 | 批判的な言及が単発（〜数件） | — | 記録のみ。反応しない |
| L1 注意 | 批判が継続（1時間で10件以上）/ 引用ポストで拡散開始 | 30分以内 | 承認者へ共有。**予約投稿を全停止**。事実確認開始 |
| L2 警戒 | まとめサイト・大型アカウントに取り上げられた | 1時間以内 | 最終責任者へエスカレーション。対外文面の準備。関係部署へ連絡 |
| L3 重大 | メディア取材・法的リスク・実害の発生 | 即時 | 経営判断。広報・法務主導。𝕏運用は指示があるまで全停止 |

### 発生時の絶対ルール

1. **一人で判断しない。** まず共有する。
2. **消す前に記録する。** 削除する場合もスクリーンショットとURLを保存。
3. **議論しない。** 個別リプライへの反論は状況を悪化させる。
4. **予約投稿を止める。** 炎上中に無関係な予約投稿が出るのが最悪の展開。
5. **時系列を記録する。** 何時に何が起きて何をしたか。DB「インシデント記録」に残す。

### 災害・重大ニュース発生時

- 地震・大規模事故・著名人の訃報など、社会的に重い出来事の発生時は **予約投稿を即時停止**。
- 再開は最終責任者の判断。目安: 【要記入】時間後 / 報道が落ち着いてから。

### 連絡先

| 状況 | 連絡先 | 手段 |
|---|---|---|
| L1 | 【要記入】 | 【要記入】 |
| L2 以上 | 【要記入】 | 【要記入】（電話必須） |
| 夜間・休日 | 【要記入】 | 【要記入】 |
