# 2-5 / 2-6 / 2-7 運用フロー・リスク管理・アカウント管理

> 1人運用なので「承認者」は存在しません。代わりに **時間を空けたセルフレビュー** で担保します。

## 1. 運用フロー（1人運用版）

```
[週末] ネタ出し → 21〜35本を一括生成（AI + テンプレ）→ DB-Bに投入
   ↓
[週末] セルフチェック（03のチェックリスト）→ DB-Aへ移し、翌週分を予約
   ↓
[平日朝] 予約分を確認（前夜に書いたものを朝の頭で読み直す＝時間差レビュー）
   ↓
[平日] 交流20〜30本 + 記事引用3〜5本
   ↓
[平日] 前日ポストの数値をDB-Aに記録
   ↓
[週末] DB-Eで週次ふりかえり → 翌週の型を決める
```

### セルフレビューの鉄則

**書いたその場で出さない。** 最低でも一晩、最短でも2時間あける。
1人運用で事故が起きるのは、ほぼ100%「勢いでその場で出したとき」です。
交流の引用リポストだけは即時でよい（ただし03-Dのスパム回避ルールを守る）。

### 一括生成を使うときの品質ゲート

AIで21〜35本まとめて作った場合、**そのまま予約しない**。次の3つだけは必ず人間が見る。

1. 数字が実体験と合っているか（月120万、11時間、2児 などの設定崩れがないか）
2. キラキラしていないか（AIは放っておくとポジティブに寄る）
3. 同じフレーズ・同じ型が3日連続で並んでいないか

## 2. リスク・炎上対応

### レベル定義

| レベル | 状況 | 初動 | 対応 |
|---|---|---|---|
| L0 監視 | 批判的な言及が単発 | — | 記録だけ。反応しない |
| L1 注意 | 批判が続く／引用で拡散が始まる | 30分以内 | **予約投稿を全停止**。事実確認。反論しない |
| L2 警戒 | 大型アカウントに取り上げられた／まとめられた | 1時間以内 | 対応方針を決める。必要なら1本だけ説明ポストを出す。それ以上は言わない |
| L3 重大 | 法的リスク／実害／本業に波及 | 即時 | 発信を全停止。事実関係を記録。必要なら専門家に相談 |

### 発生時の絶対ルール

1. **議論しない。** 個別リプライへの反論は状況を悪化させる。
2. **消す前に記録する。** 削除する場合もスクショとURLを保存。
3. **予約投稿を止める。** 炎上中に無関係な副業ポストが自動で出るのが最悪。
4. **時系列を残す。** 何時に何が起きて何をしたか。

### このアカウント固有のリスク

| リスク | 内容 | 予防 |
|---|---|---|
| **本業バレ** | 会社が副業禁止／SNS規定がある場合 | 社名・顧客・オフィスが分かる情報を一切出さない。就業規則を確認しておく |
| **家族の特定** | 子供の顔・学校 | 写真を出さない。地名を出さない |
| **収益表現への指摘** | 「稼げる」系の断定 | 03-Cの表現ルールを守る |
| **凍結・シャドウバン** | 大量の引用リポスト | 03-Dのスパム回避ルールを守る。**定型文を使わない** |
| **アカウント乗っ取り** | 資産が一瞬で消える | 2FA必須（下記） |

### 災害・重大ニュース発生時

地震・大規模事故・著名人の訃報などの発生時は **予約投稿を即時停止**。
再開の目安は報道が落ち着いてから（最低でも半日）。判断は自分ひとりなので、
**迷ったら止める** を初期値にしてください。

## 3. アカウント管理・セキュリティ

| 項目 | ルール |
|---|---|
| 二要素認証 | **必須**。認証アプリを使用。バックアップコードはオフラインで保管 |
| パスワード | 使い回さない。パスワードマネージャで管理 |
| 連携アプリ | 予約投稿ツール・分析ツールの連携を**四半期ごとに棚卸し**。使っていないものは解除 |
| 予約投稿ツール | 【要記入】 |
| バックアップ | 投稿データはDB-A / スプレッドシートに残す。𝕏が使えなくなっても資産が残る形にする |
| 単一障害点 | **𝕏だけに依存しない**。公式LINE / メールリストへの移行を常に意識する |

> 凍結は「起きないようにする」ものではなく「起きても死なないようにする」もの。
> フォロワーをLINE・メールに移しておくことが、唯一の本当の保険です。
