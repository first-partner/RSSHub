# 𝕏 運用ハブ（X Ops Hub）— Notion 構築キット

𝕏（旧Twitter）の配信ルールと参考アカウント情報を、Notion上で運用するための「箱」一式です。
このディレクトリのファイルをNotionにインポートすれば、そのまま運用を開始できる骨組みが立ち上がります。

---

## 1. Notion 全体構成（ページツリー）

```
𝕏 運用ハブ（トップページ）
│
├─ 1. 運用方針 Strategy
│   ├─ 1-1 アカウント基本設計（目的・KGI/KPI・ターゲット・立ち位置）
│   ├─ 1-2 コンテンツ方針（コンテンツピラーと投稿比率）
│   └─ 1-3 プロフィール設計（表示名 / @ID / bio / ヘッダー / 固定ポスト）
│
├─ 2. 配信ルール Rules  ★中核
│   ├─ 2-1 投稿ルール（頻度・時間帯・文体・ハッシュタグ・画像/動画・URL）
│   ├─ 2-2 トーン&マナー
│   ├─ 2-3 NG・禁止事項（法務 / 権利 / センシティブ）
│   ├─ 2-4 交流ルール（引用リポスト / リプライ / DM）★
│   ├─ 2-5 運用フロー（1人運用のセルフレビュー）
│   ├─ 2-6 リスク・炎上・凍結対策
│   └─ 2-7 アカウント管理・セキュリティ
│
├─ 3. データベース Databases
│   ├─ DB-A 投稿カレンダー
│   ├─ DB-B ネタ帳（アイデアバックログ）
│   ├─ DB-C 参考アカウント  ★
│   ├─ DB-D 参考投稿クリップ（スワイプファイル）  ★
│   ├─ DB-E KPIレポート（週次 / 月次）
│   └─ DB-F NGワード・表記統一辞書
│
├─ 4. テンプレート集（投稿フォーマット / 返信文例）
│
├─ 3-0 導線設計とファネル ★
├─ 3-2 LINEオファーとステップ配信 ★
├─ 3-3 LINE構築手順（プロラインフリー）★
├─ 3-4 𝕏記事からLINEへの橋 ★
│
└─ 5. ふりかえり・議事録
```

### なぜこの形か
- **ルール（2章）** と **実行（3章のDB）** を分ける。ルールは「変えにくい合意」、DBは「毎日動く現場」。
- **参考アカウント（DB-C）** と **参考投稿（DB-D）** を分離。アカウント単位の分析と、投稿単位の「型」の収集は目的が違うため。両者はリレーションで接続。
- **DB-A と DB-B を分ける。** 「やると決めた」ものだけカレンダーに入れ、思いつきはネタ帳に溜める。混ぜると運用が止まる。

## 2. Notion への取り込み手順

1. Notionで親ページ「𝕏 運用ハブ」を新規作成する。
2. **ルール文書（.md）**: 親ページで `/import` → **Markdown** → `rules/` 配下の各ファイルを選択。ページとして展開されます。
3. **データベース（.csv）**: 親ページで `/import` → **CSV** → `db/` 配下の各ファイルを選択。テーブルDBとして作成されます。
4. インポート後、各DBの列タイプを手で直します（CSV取り込み直後は全て「テキスト」になるため）。
   - 日付列 → `Date`、担当者列 → `Person`、ステータス/種別 → `Select` or `Multi-select`、数値 → `Number`、URL → `URL`、チェック → `Checkbox`
5. リレーションを張る: DB-D「アカウント」列 → DB-C へのRelation、DB-B「参考投稿」列 → DB-D へのRelation、DB-A「ネタ元」列 → DB-B へのRelation。
6. DB-A にビューを追加: `カレンダービュー（投稿予定日時）` / `ボードビュー（ステータス）` / `テーブル（今週）`。
7. 各CSVに入っている `【サンプル】` 行は、列の意味を示す見本です。運用開始時に削除してください。
