# これから必要な情報（ヒアリングシート）

枠は用意しました。ここから先、テンプレートの `【要記入】` を実データで埋め、
参考アカウントを実際に調べるために、以下の情報が必要です。

---

## 【必須】まずこの8つ

この8つが埋まれば、ルール文書のドラフトを完成させ、参考アカウント調査に着手できます。

| # | 質問 | なぜ必要か | 回答欄 |
|---|---|---|---|
| 1 | **どんなアカウントですか?** 企業公式 / サービス公式 / 個人（代表・専門家）/ 採用 / メディア | 主語と語り口が変わる。ルールの土台 | |
| 2 | **業種・扱う商材は?** | 薬機法・金商法など業法チェックの要否が決まる | |
| 3 | **𝕏をやる目的は?** 最終的に何が増えたら成功か | KPIとコンテンツピラーが決まる | |
| 4 | **ターゲットは誰ですか?** 属性・職種・抱える悩み | 投稿時間帯・文体・ネタが決まる | |
| 5 | **既存アカウントのURL**（あれば） | 現状のトーン・数値の把握 | |
| 6 | **参考にしたい・気になっているアカウント**（3〜10個、@IDかURL） | DB-Cの初期データになる | |
| 7 | **運用体制** 何人で回すか / 承認者は誰か / 1日に割ける時間 | 承認フローと投稿本数が決まる | |
| 8 | **投稿頻度の希望** 1日何本 / 週何日 | 現実的な運用設計 | |

## 回答をもらったあと、こちらで進めること

1. `rules/` 配下の `【要記入】` をすべて実データで埋める → 確定版ルールにする
2. 質問6・17で挙がったアカウントを **実際に調査** し、DB-C を埋める
   - 調査項目: フォロワー数 / 投稿頻度 / 投稿時間帯 / 主な形式 / トーン / コンテンツの柱 / プロフィール設計 / 固定ポスト / 収益導線
3. 各アカウントの **伸びている投稿を10〜30本クリップ** し、DB-D に「型」として蓄積
4. そこから抽出した型を `rules/06_投稿テンプレート集.md` に追記
5. 初月の投稿カレンダー（DB-A）に、最初の30本の企画を投入

### 参考アカウントの選び方（質問6を考えるときのヒント）

バランスよく選ぶと学びが多くなります。

- **同業競合（2〜3）**: 何を書いていて、何を書いていないか
- **隣接業界の巧者（2〜3）**: 業界が違うと真似しても被らない。型を盗むならここ
- **同じターゲットに届いている個人（2〜3）**: 語り口・距離感の参考
- **規模が近いアカウント（1〜2）**: 10万フォロワーのやり方は再現できない。フォロワー数が自社の2〜5倍程度が現実的な目標

> 「なんとなく有名だから」で選ばないこと。**自社のターゲットが実際にフォローしていそうか** が唯一の基準です。
