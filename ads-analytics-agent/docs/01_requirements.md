# 01. 要件定義書 — 広告・アクセス解析 AI エージェント

| 項目           | 内容                  |
| -------------- | --------------------- |
| 文書バージョン | v0.2                  |
| 作成日         | 2026-11-01            |
| ステータス     | 一部確定（10 章参照） |

## 1. 目的・背景

広告運用担当者が毎日・毎週手作業で行っている「GA4 と Google 広告の数値を集めてスプレッドシートにまとめ、前期比を見て、原因を探り、打ち手を考える」作業を自動化する。

- **集計の自動化**: 手作業の数値収集をなくす
- **分析の自動化**: 前期比・目標比・異常値・寄与度を自動で算出する
- **示唆の自動化**: 分析結果を根拠に「何が起きたか / なぜか / 次に何をするか」を優先度つきで提示する

## 2. 対象ユーザー

| ユーザー             | 主な利用シーン                           |
| -------------------- | ---------------------------------------- |
| 広告運用担当者       | 日次の異常検知、週次の改善アクション決定 |
| マーケティング責任者 | 週次/月次のサマリ確認、予算配分判断      |
| 経営層（任意）       | 月次の要約（KPI と結論のみ）             |

## 3. スコープ

### 3.1 対象範囲（Phase 1 = MVP）

- データソース: **GA4**、**Google 広告**
- 集計: 日次・週次・月次
- 分析: 期間比較、目標比、異常検知、寄与度分解、ファネル、キャンペーン/キーワード/検索語句の効率分析
- 示唆出し: 根拠つき・優先度つきの改善提案
- 出力: Google スプレッドシート（スライドに展開できる構造で出力）
- 対話: 「先週 CV が落ちた理由は？」のような追加質問に答える

### 3.2 対象外（Phase 1）

- 広告の **自動変更**（入札・予算・停止）。Phase 1 は **読み取り専用**。提案のみ行い、実行は人が行う
- Meta / Yahoo! / TikTok など他媒体（Phase 2 以降で拡張可能な設計にする）
- CRM・売上データとの統合（Phase 3）

## 4. 機能要件

### F1. データ収集

| ID   | 要件                                                                                                                                                                  | 優先度 |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| F1-1 | GA4 Data API でセッション、ユーザー、エンゲージメント率、CV（キーイベント）、収益を、日付 × チャネル × 参照元/メディア × キャンペーン × LP × デバイスで取得する       | 必須   |
| F1-2 | Google Ads API（GAQL）でキャンペーン / 広告グループ / キーワード / 検索語句 / 広告の表示回数、クリック、費用、CV、CV 値、インプレッションシェア、品質スコアを取得する | 必須   |
| F1-3 | 複数の GA4 プロパティ・複数の広告アカウント（MCC 配下）に対応する                                                                                                     | 必須   |
| F1-4 | GA4 の確定遅延（48〜72 時間）を考慮し、直近 3 日分は毎回再取得する（上書き）                                                                                          | 必須   |
| F1-5 | 取得失敗時はリトライ（指数バックオフ）し、それでも失敗したら通知する                                                                                                  | 必須   |
| F1-6 | 過去データの一括取り込み（バックフィル、最大 13 か月）ができる                                                                                                        | 推奨   |

### F2. 集計・データ統合

| ID   | 要件                                                                                                 | 優先度 |
| ---- | ---------------------------------------------------------------------------------------------------- | ------ |
| F2-1 | GA4 と Google 広告のデータを、日付 × キャンペーン（`utm_campaign` / gclid 連携）の共通キーで結合する | 必須   |
| F2-2 | 派生指標を算出する: CTR、CPC、CVR、CPA、ROAS、CV 単価、直帰率相当（1 − エンゲージメント率）          | 必須   |
| F2-3 | KPI 定義・目標値（月次予算、目標 CPA / ROAS 等）を設定ファイルで管理する                             | 必須   |
| F2-4 | 月次の予算消化ペース（着地予測）を算出する                                                           | 必須   |

### F3. 分析（決定的ロジック）

| ID   | 分析               | 内容                                                                                                                                         | 優先度 |
| ---- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| F3-1 | 期間比較           | 前日・前週同曜日・前週・前月・前年同期比                                                                                                     | 必須   |
| F3-2 | 目標比             | KPI 目標に対する達成率、予算消化ペース                                                                                                       | 必須   |
| F3-3 | 異常検知           | 過去 28 日の曜日別ベースラインからの乖離（ロバスト z スコア）。費用急増・CV 急減・CVR 急変・計測停止の疑い（CV = 0 が続く等）                | 必須   |
| F3-4 | 寄与度分解         | KPI 変化を「キャンペーン別」「デバイス別」「チャネル別」に分解し、変化を最も説明する要因を特定する。CPA 変化を CPC 要因と CVR 要因に分解する | 必須   |
| F3-5 | 効率分析           | 費用が多いのに CV が 0 / 少ないキーワード・検索語句（無駄な費用）、CPA が目標を大きく超える広告グループ                                      | 必須   |
| F3-6 | 機会分析           | 予算制限でインプレッションシェアを失っている高 ROAS キャンペーン、CVR の高い LP / 検索語句                                                   | 必須   |
| F3-7 | ファネル分析       | セッション → エンゲージ → 主要イベント → CV の段階別離脱と変化                                                                               | 推奨   |
| F3-8 | 計測健全性チェック | GA4 CV と広告 CV の乖離、`(not set)` 比率の急増、UTM 欠落                                                                                    | 推奨   |

### F4. 示唆出し（AI）

| ID   | 要件                                                                                                          | 優先度 |
| ---- | ------------------------------------------------------------------------------------------------------------- | ------ |
| F4-1 | F3 の結果（数値・表）だけを入力にし、「事実 → 解釈（仮説） → 打ち手 → 期待効果 → 確度」の形式で示唆を生成する | 必須   |
| F4-2 | すべての示唆に **根拠の数値**（指標名・期間・値・比較値）を付ける。根拠のない主張は出力しない                 | 必須   |
| F4-3 | 示唆を **影響額（円換算）× 確度 × 実行容易性** で優先度付けし、上位 3〜5 件に絞る                             | 必須   |
| F4-4 | 出力は構造化 JSON（スキーマ検証）→ レポート文章の 2 段階で生成する                                            | 必須   |
| F4-5 | 示唆に含まれる数値が分析結果と一致するか機械的に検証する（ハルシネーション対策）                              | 必須   |
| F4-6 | 過去の示唆と、その後の実績（実行有無・効果）を記録し、次回の示唆に反映する                                    | 推奨   |
| F4-7 | 自社の運用ルール・業界知識（例: 「ブランド KW は停止しない」）をナレッジとして与えられる                      | 推奨   |

### F5. レポート出力・配信

出力の中心は **Google スプレッドシート**。後でクライアント報告用のスライドに起こせるよう、レポートは「中間データ（ReportModel）→ 出力先ごとの描画」の 2 段構成にする（詳細は `04_reporting-design.md`）。

| ID   | 要件                                                                                                                                         | 優先度  |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| F5-1 | 週次・月次レポートをスプレッドシートに出力する（サマリ / KPI 推移 / キャンペーン明細 / 示唆 / 示唆ログ の各タブ）                            | 必須    |
| F5-2 | スプレッドシート上にグラフ（KPI 推移、寄与度、費用構成）を **ネイティブのグラフ** で作成する（スライドにリンク貼り付けできるようにするため） | 必須    |
| F5-3 | レポート内容を出力先に依存しない中間データ（ReportModel: KPI タイル、表、グラフ定義、示唆）として保存する                                    | 必須    |
| F5-4 | 色・フォント・ロゴなどの見た目をテーマ設定ファイルで管理し、全出力先で共通に使う                                                             | 必須    |
| F5-5 | クライアント報告用の **Google スライド** を、テンプレートのスライドに数値・グラフ・示唆を差し込んで自動生成する                              | Phase 2 |
| F5-6 | クライアントごとに「見せる指標・見せない指標（例: 内部メモ、マージン）」を設定できる                                                         | Phase 2 |
| F5-7 | 日次: 異常があった場合のみ通知（メールまたは Slack）                                                                                         | Phase 2 |
| F5-8 | PDF 出力（スライドから書き出し）                                                                                                             | Phase 3 |

### F6. 対話（アドホック分析）

| ID   | 要件                                                                                                | 優先度 |
| ---- | --------------------------------------------------------------------------------------------------- | ------ |
| F6-1 | Slack または Claude Code / claude.ai から自然言語で質問できる（例: 「10 月の CPA 悪化の主因は？」） | 推奨   |
| F6-2 | エージェントは登録済みツール（データ照会・分析関数）だけを使って回答する                            | 推奨   |

## 5. 非機能要件

| 区分         | 要件                                                                                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| セキュリティ | Google API は **読み取り専用スコープ**（`analytics.readonly`、Ads は読み取りのみ使用）。認証情報は GitHub Actions Secrets / Secret Manager 等で管理し、リポジトリに置かない |
| データ保護   | 個人を特定できる情報は扱わない（GA4 集計データのみ）。LLM には集計済みの数値のみ送る                                                                                        |
| 正確性       | 数値計算はすべてコードで行い、LLM に計算させない。示唆内の数値は自動検証する                                                                                                |
| 可用性       | 日次バッチの失敗は 1 時間以内に通知。再実行は冪等（同じ日付を再実行しても重複しない）                                                                                       |
| 性能         | 日次バッチ 10 分以内（1 アカウント・1 プロパティあたり）                                                                                                                    |
| コスト       | LLM 呼び出しは 1 レポートあたり数回に抑える。プロンプトキャッシュを使う                                                                                                     |
| API 制限     | GA4 のクォータ（トークン制）、Google Ads API の 1 日あたり操作数を超えないようにする                                                                                        |
| 拡張性       | データソースはプラグイン形式（Connector インターフェース）で追加できる                                                                                                      |
| 監査性       | 各レポートについて、入力データ、プロンプト、出力、モデル名をログに保存する                                                                                                  |

## 6. KPI 定義（目標値は要確認）

| KPI                    | 定義                                                | 主ソース                |
| ---------------------- | --------------------------------------------------- | ----------------------- |
| 広告費                 | Google 広告 `metrics.cost_micros` / 1,000,000       | Google 広告             |
| 表示回数               | Google 広告 `metrics.impressions`                   | Google 広告             |
| クリック数             | Google 広告 `metrics.clicks`                        | Google 広告             |
| CTR                    | クリック数 ÷ 表示回数                               | Google 広告             |
| CPC                    | 広告費 ÷ クリック数                                 | Google 広告             |
| インプレッションシェア | `metrics.search_impression_share`（検索のみ）       | Google 広告             |
| CV                     | GA4 キーイベント（例: `purchase`, `generate_lead`） | GA4（広告側 CV も併記） |
| CPA                    | 広告費 ÷ CV                                         | 統合                    |
| ROAS                   | 収益 ÷ 広告費                                       | 統合                    |
| セッション / ユーザー  | GA4 標準                                            | GA4                     |
| CVR                    | CV ÷ セッション（サイト）／ CV ÷ クリック（広告）   | 両方                    |

## 7. 前提・制約

- Google Ads API の利用には **開発者トークン**（Basic アクセス以上）と OAuth クライアントが必要。**開発者トークンは取得済み**（Basic アクセス承認済み。トークン文字列はマネージャーアカウントの「API センター」で確認する）
- Basic アクセスの上限は 1 日 15,000 オペレーション。本ツールの想定利用量（1 日数十〜数百リクエスト）で十分
- トークン申請時の用途は「社内用・レポート機能を含むフルサービスツール」。クライアント本人がツールを直接操作する形に変える場合は、Google への用途変更の届け出が必要になる
- GA4 Data API には GCP プロジェクトとサービスアカウント（GA4 プロパティへの閲覧権限付与）が必要
- GA4 のデータは確定まで 24〜72 時間かかるため、日次レポートは「前日の速報値」と明記する
- BigQuery は使わない（未設定のため）。データは API から直接取得し、スプレッドシートに保存する（`02_architecture.md` 参照）

## 8. 受け入れ基準（MVP）

1. 指定アカウントの前日分データが毎朝自動で取り込まれ、管理画面の数値と一致する（誤差 1% 以内、GA4 の確定遅延分を除く）
2. 週次レポートが月曜 9 時までにスプレッドシートに出力されている
3. 週次レポートの示唆がすべて根拠の数値を含み、数値検証を通過している
4. 意図的に仕込んだ異常（テストデータで費用を 3 倍にする等）を日次で検知できる
5. 運用担当者による評価で、示唆の 60% 以上が「妥当・実行検討に値する」と判定される

## 9. ロードマップ

| フェーズ       | 期間目安 | 内容                                                                                            |
| -------------- | -------- | ----------------------------------------------------------------------------------------------- |
| Phase 0        | 1 週     | 認証準備（GCP プロジェクト、OAuth、既存の開発者トークンの確認）、KPI・目標の確定                |
| Phase 1（MVP） | 3〜4 週  | GA4 + Google 広告の取得、集計、分析（F3-1〜F3-6）、示唆、週次スプレッドシート出力               |
| Phase 2        | 3〜4 週  | Google スライド自動生成、日次異常通知、月次レポート、対話（F6）、示唆の効果トラッキング（F4-6） |
| Phase 3        | 適宜     | 他媒体（Meta 等）、CRM / 売上連携、承認つき自動実行（予算変更など）                             |
