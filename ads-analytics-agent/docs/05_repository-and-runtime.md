# 05. リポジトリと実行環境

## 1. リポジトリを分けるか

### 1.1 分けない（RSSHub リポジトリに置いたまま）場合のデメリット

| #   | デメリット                    | 内容                                                                                                                                                                                    |
| --- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **公開されている**            | `first-partner/RSSHub` は公開リポジトリ（RSSHub のフォーク）。設計書・コード・設定（アカウント ID、KPI 目標、クライアント名など）が誰でも見られる。報告対象のクライアント情報を置けない |
| 2   | 秘密情報の漏えいリスク        | 誤って認証情報をコミットすると即公開される。公開リポジトリは自動収集ボットに常に監視されている                                                                                          |
| 3   | 無関係な仕組みが動く          | RSSHub の lint・フォーマッタ・テスト・コミット時のフック（husky）が本ツールのファイルにも適用される。依存パッケージの取得も重い（Node.js 一式）                                         |
| 4   | 本家との同期で衝突            | フォーク元（DIYgod/RSSHub）を取り込むたびに履歴が混ざり、取り込みや競合解消が面倒になる                                                                                                 |
| 5   | 権限を分けられない            | 本ツールだけを他の人に見せる・触らせる、ができない                                                                                                                                      |
| 6   | GitHub Actions の設定が混ざる | RSSHub のワークフローと本ツールの定期実行が同じ場所に並び、管理しにくい                                                                                                                 |
| 7   | AI への指示が混ざる           | RSSHub 用の開発ルール（`AGENTS.md`）が本ツールの開発時にも読み込まれる                                                                                                                  |

**メリット**は「準備がいらない」ことだけ。本ツールは RSSHub と関係がないため、分けることを強く推奨する。

### 1.2 新しいリポジトリに分ける手順

#### 手順 1: GitHub でリポジトリを作る（ブラウザ）

1. <https://github.com/organizations/first-partner/repositories/new> を開く（個人アカウントに作る場合は <https://github.com/new>）
2. 設定:
    - Repository name: `ads-analytics-agent`（任意）
    - **Private を選ぶ**
    - 「Add a README」などのチェックは **すべて外す**（空のリポジトリにする）
3. 「Create repository」を押す

#### 手順 2: Claude（GitHub アプリ）にアクセスを許可する

- <https://github.com/apps/claude/installations/select_target> から `first-partner` を選ぶ
- 「Only select repositories」になっている場合は、新しいリポジトリを追加する（「All repositories」なら作業不要）

#### 手順 3: ファイルを移す（Claude が実行）

リポジトリ名を教えていただければ、このセッションに追加して、これまでの設計書をコミット履歴ごと移します。手元で行う場合のコマンドは以下です。

```bash
git clone https://github.com/first-partner/RSSHub.git && cd RSSHub
```

```bash
git checkout claude/serene-bell-7r30kj
```

```bash
git subtree split --prefix=ads-analytics-agent -b ads-agent-export
```

```bash
git push https://github.com/first-partner/ads-analytics-agent.git ads-agent-export:main
```

#### 手順 4: RSSHub 側を片付ける

移行後、RSSHub の作業ブランチから `ads-analytics-agent/` を削除する（または作業ブランチごと削除する）。公開済みの履歴には残るため、**移行前も移行後も、RSSHub 側には機密情報を書かない**。

## 2. 実行環境の比較

前提: BigQuery なし、出力はスプレッドシート中心、1 日 1 回〜週 1 回の定期実行、処理時間は 1 回 数分〜10 分程度。

| 観点                         | GitHub Actions                                                               | GCP（Cloud Run Jobs ＋ Cloud Scheduler）      | 手元の PC（cron / タスクスケジューラ） | Google Apps Script（GAS）                                             |
| ---------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------- | -------------------------------------- | --------------------------------------------------------------------- |
| 初期設定                     | ◎ 設定ファイル 1 つ                                                          | △ GCP プロジェクト、コンテナ、権限設定        | ◎ ほぼ不要                             | ◯ スプレッドシートに付けるだけ                                        |
| 費用                         | ◎ 非公開リポジトリでも月 2,000 分まで無料（Free プラン）。本用途なら無料枠内 | ◯ 無料枠が大きく、本用途ならほぼ 0〜数百円/月 | ◎ 0 円（電気代のみ）                   | ◎ 0 円                                                                |
| 安定性                       | ◯ 混雑時に定時から数分〜数十分遅れることがある                               | ◎ 定時に確実に実行                            | × PC の電源・スリープ・ネット次第      | ◯ 安定。ただし 1 回 6 分の実行時間制限                                |
| 秘密情報の管理               | ◯ Actions Secrets                                                            | ◎ Secret Manager                              | △ PC 内のファイル                      | △ スクリプト プロパティ                                               |
| Python / 分析ライブラリ      | ◎ 自由に使える                                                               | ◎ 自由に使える                                | ◎ 自由に使える                         | × JavaScript のみ。統計処理や Claude 連携のコードを自前で書く必要あり |
| 実行ログ・失敗通知           | ◯ 画面で確認、失敗時メール                                                   | ◎ Cloud Logging、細かいアラート               | × 自分で作る                           | ◯ 失敗時メール                                                        |
| 手動での再実行               | ◎ ボタン 1 つ（日付を指定して実行可）                                        | ◯ コマンドまたは画面                          | ◯                                      | ◯                                                                     |
| 将来の拡張（対話・Web 画面） | △ バッチ専用                                                                 | ◎ Web サービスも同じ基盤で動く                | ×                                      | △                                                                     |
| データ保存                   | △ 実行ごとに消える → スプレッドシート / Drive に保存                         | ◯ 同左（Cloud Storage も使える）              | ◎ PC に残る                            | ◯ スプレッドシートに直接                                              |

### 推奨

- **MVP は GitHub Actions**: 設定が最小で、無料枠内で動き、Python の分析ライブラリと Claude Agent SDK をそのまま使える。リポジトリと一体で管理でき、日付を指定して手動で再実行するのも簡単
- **Phase 2 以降で GCP に移す**: 対話機能（Slack などからの質問）や Web 画面を作る段階、または定時実行の厳密さが必要になった段階で Cloud Run に移す。コードはコンテナ化しておけばそのまま動く
- 手元の PC は開発・動作確認用。GAS は分析ロジックを JavaScript で書き直す必要があり、本設計（Python で分析 → Claude で示唆）とは相性が悪いため採用しない
